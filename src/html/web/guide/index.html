WASM MASM x86 Editor user guide

Write, compile, link and run MASM (Microsoft Macro Assembler) assembly online with WASM MASM x86 Editor. The editor uses JWasm to assemble source code, JWlink to create executables, and BoxedWine to run 32-bit x86 programs. The Irvine32 library is included. A program split into several files is linked as Microsoft's MASM and LINK link it, with no project file, and a module-definition file builds a DLL: see Programs in several files and DLLs.

This manual covers the browser editor, its toolbar controls and the steps to build and back up a program. Use a browser with JavaScript and WebAssembly enabled; no local assembler installation is required.

Compile and run your first program

  1. Open the editor. Wait for the terminal to load the command prompt.
  2. Create a source file. In the file explorer, select the yellow page icon (Create new assembly (.asm) text file). Enter hello.asm and press Enter.
  3. Enter the code. Paste the Irvine32 example below into the editor. Pause briefly after editing to allow automatic saving.
  4. Build the program. Select Compile, link and run .asm file, the first button in the main toolbar. It assembles the open source file, links the object file and starts the executable.
  5. Check the terminal. A successful run prints Hello from MASM!. Build errors appear in the same terminal. If your program requests input, click inside the terminal before typing.

After changing source code, use Compile, link and run .asm file again. Run compiled binary runs the existing executable without rebuilding it.

Irvine32 example: print a message

INCLUDE Irvine32.inc
.data
message BYTE "Hello from MASM!", 0

.code
main PROC
    mov edx, OFFSET message
    call WriteString
    call Crlf
    exit
main ENDP
END main

message contains a null-terminated string. mov edx, OFFSET message passes its address to WriteString. Crlf adds a line break, and exit ends the program.

Expected output

Hello from MASM!

Print text in any language

A string in your source is stored as UTF-8. The terminal starts with code page 437, as a US English Windows console does, so programs that print its box-drawing characters keep working; to print UTF-8, switch the console to code page 65001 first. Irvine32.inc does not declare SetConsoleOutputCP, so the program declares it:

INCLUDE Irvine32.inc
SetConsoleOutputCP PROTO, wCodePageID:DWORD

.data
msg BYTE "Hello, 世界! Привет! مرحبا", 0dh, 0ah, 0

.code
main PROC
    INVOKE SetConsoleOutputCP, 65001   ; the console reads the bytes as UTF-8
    mov edx, OFFSET msg
    call WriteString
    exit
main ENDP
END main

Instead of calling SetConsoleOutputCP, you can type chcp 65001 in the terminal before running a program. The example builds unchanged with Microsoft MASM and the standard Irvine32 library.

Programs in several files and DLLs

A program can be split into modules, with no project file: MASM's own END, PROTO and INCLUDE say what goes together. Make these three files in one folder, open main.asm and select Compile, link and run .asm file. It prints 42.

; math.inc: what math.asm offers
INCLUDE Irvine32.inc
AddTwo PROTO                ; EAX = EAX + EBX
INCLUDE math.inc

.code
AddTwo PROC
    add eax, ebx
    ret
AddTwo ENDP
END
INCLUDE math.inc

.code
main PROC
    mov eax, 20
    mov ebx, 22
    call AddTwo
    call WriteDec           ; prints EAX
    call Crlf
    exit
main ENDP
END main

To make math.inc, choose Include file (.inc) under Type in the Create file window.

What is linked follows from the sources:

  • A module is an .asm file whose END names no entry point. END main makes a program.
  • A program links the modules that define what it uses (what it calls, or declares with PROTO or EXTERN) and its libraries do not.
  • Modules are found in the program's folder, the folders below it, and the folders of the .inc files it includes.
  • A name a library defines, such as Irvine's WriteString, comes from the library: a module defining its own WriteString is not linked for it.

With a module open, Compile, link and run .asm file builds and runs the program that uses it, and Run compiled binary runs that program. A module that two programs use is only assembled, and a message names the programs. When two files define a name the program needs, a message names them and nothing is built: keep one, or give the program a folder of its own.

In the terminal, assemble main math builds the same program by hand from its folder: each file is assembled into the bin folder beside it, then the objects are linked, the program's first, into bin\main.exe, which runs. assemble /c math only assembles, and an .obj file in the list is linked as it is: assemble main bin\math.obj. Quote a name that holds spaces. A name with % in it cannot be built: the terminal's cmd changes it.

Build a DLL

A program builds as a DLL when a .def file of the same name beside it starts with LIBRARY and the DLL's name. Compile, link and run .asm file then makes bin\mathdll.dll and its import library bin\mathdll.lib, and runs nothing; by hand, assemble /dll mathdll does the same, exporting the procedures marked PROC EXPORT. Give a DLL a name in ASCII characters, in its file names and after LIBRARY: a program finds the DLLs it imports by names that Windows reads in its ANSI code page. Make these files in a folder of their own:

INCLUDE Irvine32.inc

.code
DllEntry PROC hInst:DWORD, reason:DWORD, reserved:DWORD
    mov eax, TRUE           ; the DLL loads
    ret
DllEntry ENDP

AddTwo PROC a:DWORD, b:DWORD
    mov eax, a
    add eax, b
    ret
AddTwo ENDP
END DllEntry
LIBRARY mathdll
EXPORTS
    AddTwo

A program in the same folder uses the DLL through its import library. Build mathdll.asm first, then usedll.asm, which prints 42:

INCLUDE Irvine32.inc
INCLUDELIB bin\mathdll.lib
AddTwo PROTO, a:DWORD, b:DWORD

.code
main PROC
    INVOKE AddTwo, 40, 2
    call WriteDec
    call Crlf
    exit
main ENDP
END main

Manage and back up files

Open and rename files

The file explorer shows the terminal's D: drive as a tree, and below it any other drive a share link brought, each with its letter. Click a file to open it. Checking its box selects it for download or deletion; it does not open it. Double-click a file to rename it, then press Enter, or press F2 (or right-click and choose Rename) to rename a file, a folder or a drive. As in Windows, clicking the name of the selected one once more, then waiting a moment, renames it too. Keep the .asm extension on assembly source files.

Files other than .asm show a bar above the editor: Edit as text opens them in the editor, View in hex in the hex viewer. Binary files such as .exe and .obj open in hex; other files open as text. Include files (.inc) and module-definition files (.def) always open as text, with their syntax highlighted.

Folders

Click a folder to select it; double-click it, or click its +/- box, to open or close it. New files, new folders, uploads and imports go into the selected folder (otherwise into the folder of the open file, otherwise into D:\); each dialog names that folder.

To move files or folders, drag them onto a folder or onto a drive such as (D:), from one drive to another as well. On a touch screen, press and hold, then drag. Without dragging, right-click and choose Cut, then right-click the destination and choose Paste (Ctrl+X, Ctrl+V). Dragging a checked item moves every checked item. The tree also works from the keyboard: arrow keys, Enter, Space (check), F2, Delete and Shift+F10 (the menu).

A program in a folder is built and run in that folder, so an INCLUDE of a file next to it works as on Windows. The tree scrolls smoothly with thousands of files, and Select all checks every one of them.

Names and text in any language

File and folder names and the text you type or paste can use any language, and the terminal shows them. Programs are built and run under their real names: the assembler, the linker and INCLUDE accept names in any language.

Assembly sources (.asm and .inc) are saved as UTF-8 text without a byte order mark, which is what Microsoft MASM reads. A source saved by another editor with a byte order mark (UTF-8 with BOM, or UTF-16, which Notepad calls "Unicode") is converted to plain UTF-8, with the same text, when you save it or build.

Automatic saving and local storage

Source edits save automatically in this browser after a short pause in typing. Allow that pause before switching files, building, downloading or closing the page. Files are stored in IndexedDB; editor preferences are stored in local storage.

Keep a downloaded backup. Browser storage stays with this browser and device. It does not sync to an account, and clearing site data removes it. The floppy disk button downloads a copy to your device.

Download and restore a project

  1. Check the files and folders you need, or use Select all.
  2. Select Save selected file(s). More than one file, or any folder, downloads as one ZIP archive with the same folders.
  3. To restore a backup, use Add file(s) to project, choose the ZIP and select Extract here: its files and folders, empty ones included, come back as they were. Import a folder brings in a folder from your device the same way.

Copy Console Text

To copy text from the console highlight it with your mouse by click dragging over it and type: Ctrl + shift + C or cmd + shift + C to copy it to your clipboard

Scroll the terminal

The terminal keeps the last 500 lines of output. To see earlier ones:

  • Mouse wheel: each notch scrolls three rows on Windows and Linux (on Windows, as many as the system's mouse setting for lines to scroll); on a Mac, as far as a page scrolls.
  • Trackpad: the rows follow your fingers, one row at a time.
  • Scrollbar: click an arrow to scroll one row, or hold it down to keep scrolling; click the track above or below the thumb (the box) to scroll by the window's height less one row; drag the thumb to go anywhere in the 500 lines.

A program that reads the mouse itself, in a window with no earlier lines to scroll, gets one wheel event for each row: three for a notch.

Troubleshoot builds and the terminal

The assembler or linker reports an error
Read the first error in the terminal and check the referenced source line or symbol. Correct the source, then compile again. For the example above, keep INCLUDE Irvine32.inc and END main as shown.
The program runs an older version of the code
Wait briefly after your last edit, then use Compile, link and run .asm file. Run compiled binary does not rebuild the executable.
Typing does not reach the program or editor
Click inside the terminal to enter program input, or inside the editor to edit source. If Vim mode is enabled, press i to insert text or turn Vim mode off.
A notice says the program stopped
The program ended with an exception, as it would on Windows: the notice names it (an access to an address it does not own, a division by zero, an illegal or privileged instruction) with a hint. When the program executed an instruction the emulated processor (a Pentium 4 with MMX, SSE and SSE2) should run, the notice says so and offers Report bug: it opens a GitHub issue filled in with the instruction and its bytes, which you can check before submitting.
A notice says the terminal stopped
The emulator itself failed; your program is not the cause and your files are safe. Select Report bug to open a filled-in GitHub issue, then Reset terminal.
A panel is missing
Use its Show / hide toolbar control. If zen mode is active, turn it off to restore the editor, terminal and file explorer.

Reset a terminal that does not respond

  1. Select Cancel the running command (Ctrl+C) to interrupt the program.
  2. If the terminal still does not respond, select Reset command prompt and wait for the terminal to restart.
  3. If restarting does not resolve the problem, open Hard reset. Leave Also delete all my files unchecked, wait for the confirmation countdown and select Hard Reset.

A hard reset rebuilds the terminal environment and may take longer than a normal startup. Files in the file explorer, on every drive, are restored automatically, and the panes keep their layout. Delete Extra Drives... in the same window removes the drives other than D:, and Restore Default Layout puts the panes back in their default places.

Deleting files during a hard reset cannot be undone. Select Also delete all my files only if you intend to erase the project and any files left from an older version. Download a backup first.

Assembler and library compatibility

The build tools are JWasm and JWlink, which support MASM-compatible syntax. The editor does not use Microsoft's MASM executables, but it works as Microsoft MASM (ML.exe 14) does: sources stay plain UTF-8, instructions are encoded as ML encodes them, and what ML refuses is refused here too (JWasm's own syntax extensions, and names ML reserves, such as k1, an AVX-512 register there). Code written here also builds with ML.exe. The browser runtime is a 32-bit Wine environment running through BoxedWine and WebAssembly. Use 32-bit x86 programs with Irvine32; 64-bit Windows executables cannot run here.

INCLUDE Irvine32.inc loads the bundled Irvine32 declarations. The bundled build command handles the library paths and linking for the example above. Other included headers are Macros.inc, SmallWin.inc, VirtualKeys.inc and GraphWin.inc.

The library files are those of Kip Irvine's current distribution. Only Clrscr in Irvine32.lib is rewritten to clear the screen faster, with the same result, so a program written here links the same way with the standard library.

INCLUDE finds a file as Microsoft MASM (ML 14) does. A name with a drive letter, or starting with \, is taken as written. A name starting with .\ or ..\ is looked for in the folder the build runs in: the program's. Any other name is looked for beside the file that includes it, then beside each file including that one, out to the program, and then in C:\files\irvine.

INCLUDELIB finds a library as Microsoft's LINK does: in the program's folder, then in C:\files\irvine and C:\files\lib. A name without an extension gets .lib.

Irvine's files are also in C:\Irvine, where Kip Irvine's Visual Studio setup puts them, so a source that writes INCLUDE C:\Irvine\Irvine32.inc builds here unchanged.

C:\files\lib holds import libraries for the Windows DLLs of the terminal (Wine 6.0), such as gdi32.lib, advapi32.lib, winmm.lib and msvcrt.lib (the C library's printf): declare the function with PROTO and name its library, as in INCLUDELIB gdi32.lib. kernel32.lib and user32.lib come with Irvine32 and are always linked.

The emulated processor is a Pentium 4: the 386 and 486 integer instructions, x87, MMX, SSE and SSE2. Instructions of later processors (SSE3 and newer) stop the program with a notice that names them.

Support and resources

For a reproducible problem, report an issue with your browser version, the steps you followed, the relevant source code and the terminal error. The project repository contains the source code; desktop releases are available separately.
